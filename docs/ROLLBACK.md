# لایه ۰۵ — انتشار و مسیر بازگشت

## انتشار
```bash
make deploy ENV=production      # یا: ops/deploy.sh production
```
هفت مرحله، همه‌شان خودکار: preflight → lint و تست → **پشتیبان‌گیری قبل از هر تغییر**
→ ساخت استاتیک اثرانگشت‌دار → migration رو به جلو → ثبت release → restart و بررسی سلامت.
اگر `/api/readyz` بعد از restart سبز نشود، اسکریپت با خطا تمام می‌شود و به شما
می‌گوید `ops/rollback.sh` بزنید.

## بازگشت
```bash
make rollback                   # به نسخه‌ی قبلی
ops/rollback.sh <release-id>    # به یک نسخه‌ی مشخص
```
پنج release آخر در `releases/` نگه داشته می‌شوند. `CURRENT_RELEASE` نسخه‌ی فعال را دارد.

## این مسیر واقعاً استفاده شده است

تمرین ۲۰۲۶/۱۰/۰۱، محیط drill روی پورت ۸۰۹۹:

```
# release 3 با یک رگرسیون عمدی منتشر شد
$ ops/deploy.sh drill
✔ deployed 20261001T070751Z-e4b85ba to drill
$ curl /api/healthz
{"marker":"RELEASE-3-REGRESSION","ok":true,"version":"1.1.0-BAD",...}   ← رگرسیون روی هواست

# بازگشت
$ ENVNAME=drill ops/rollback.sh
rolling back: 20261001T070751Z-e4b85ba -> 20261001T070724Z-4f924e8
started drill on :8099 pid=10477
✔ rolled back to 20261001T070724Z-4f924e8
rollback took 3050 ms

$ curl /api/healthz
{"ok":true,"version":"1.1.0-BAD",...}                                   ← رگرسیون رفت
$ grep -c RELEASE-3 api/main.py
0
```

| سنجه | مقدار |
|---|---|
| **زمان بازگشت اندازه‌گیری‌شده** | **۳٫۰۵ ثانیه** |
| تأیید | رشته‌ی رگرسیون هم از پاسخ API و هم از کد روی دیسک حذف شد |
| داده‌ی از دست رفته | صفر — بازگشت فقط کد را برمی‌گرداند، نه پایگاه‌داده را |

## نکته‌ی مهم درباره‌ی migrationها
بازگشت کد، **migration را برنمی‌گرداند**. چون migrationها فقط رو به جلو هستند،
هر تغییر اسکیما باید با نسخه‌ی قبلی کد هم سازگار باشد (افزودن ستون nullable،
نه حذف یا تغییر نام). اگر مجبور به تغییر شکستنی شدید، آن را به دو انتشار بشکنید:
۱) ستون جدید را اضافه و پر کنید، ۲) در انتشار بعدی ستون قدیمی را حذف کنید.

## یک چیزی که این تمرین پیدا کرد
اولین اجرای `ops/deploy.sh` شکست خورد، چون تست‌ها `DB_PATH` را از محیط انتشار
به ارث می‌بردند و می‌توانستند پایگاه‌داده‌ی واقعی را پاک کنند. برطرف شد
(کامیت `4f924e8`): `tests/conftest.py` حالا محیط را **تحمیل** می‌کند نه پیشنهاد،
`ops/deploy.sh` تست‌ها را با `env -u` اجرا می‌کند، و
`test_suite_cannot_touch_a_real_db` نگهبان آن است.
