# Runbook — آسا فیزیو

## راه‌اندازی از صفر

```bash
make install                      # نصب وابستگی‌ها
cp .env.example .env.staging      # و پر کردن SECRET_KEY و کانال تحویل
make build                        # ساخت سایت + بسته‌ی public/ با نام‌های اثرانگشت‌دار
make migrate                      # اعمال migrationها
ADMIN_USER=owner ADMIN_PASSWORD='...' python3 -m ops.seed
make serve                        # اجرا روی PORT
```

سایت روی `/` و پنل کارکنان روی `/admin`.

## دستورهای روزمره

| کار | دستور |
|---|---|
| انتشار | `make deploy ENV=production` |
| بازگشت به نسخه‌ی قبل | `make rollback` |
| پشتیبان‌گیری | `make backup` |
| بازیابی | `ops/restore.sh data/backups/asa-<stamp>.db.gz` |
| تست‌ها | `make test` |
| سنجش گلوگاه | `make loadtest` |

## وقتی چیزی خراب شد

1. **کد پیگیری را از کاربر بگیرید** (در پیام خطا نشان داده می‌شود) و در لاگ‌ها جست‌وجو کنید:
   `grep '<trace_id>' data/staging.log`
2. `curl /api/readyz` — وضعیت پایگاه‌داده و قطع‌کننده را می‌گوید.
3. `data/alerts.log` — هر خطای مدیریت‌نشده با همان کد پیگیری اینجاست.
4. اگر قطع‌کننده باز مانده: پنل → وضعیت سامانه → «بستن قطع‌کننده».
5. اگر انتشار اخیر مقصر است: `make rollback`.

## وقتی درخواست نوبتی به کلینیک نرسید

- پنل، ستون «تحویل نشد» را قرمز نشان می‌دهد.
- دکمه‌ی «ارسال دوباره به کلینیک» روی همان ردیف.
- اطلاعات بیمار از دست نمی‌رود؛ همیشه در پایگاه‌داده هست حتی اگر اطلاع‌رسانی شکست بخورد.
